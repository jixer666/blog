## 问题背景

公司的 IM 内部通讯在发送消息，数据量不是很大大约1000条左右，因为发送一条消息消息，包含了很多的对数据库 SqlServer 表操作逻辑，所以在成功推送了7、8条数据后出现了死锁问题

## 问题分析

首先是对死锁的分析，死锁产生的四个条件：

- 互斥条件
- 不可剥夺条件
- 请求和保持条件
- 循环等待条件

可以看到是在查询的时候出现了死锁

**为什么查询会出现死锁呢？**整个过程的逻辑是顺序执行的，先是保存，等保存完了才执行的查询，按照我的理解，保存的加的排他锁已经被释放掉了，并不会影响查询的共享锁，而且下一次的循环操作的又是另一组数据，并不是同一行，并不会影响当前的数据

笔者从这里就感觉到了很奇怪，于是打开了 Navicat 模拟一下事务下 Sql 对查询 Sql 的影响，发现具体在一个事务的下，只要这个事务没执行完，关于事务里的所有涉及的表都没法进行任何操作，**锁由行级锁升级成为了表级锁，将整个表锁住了**！具体的 Sql 如下：

```sql
BEGIN TRANSACTION;
INSERT INTO test (id, content) VALUES ('311', '12312');

-- 检查当前持有的锁
SELECT 
    request_session_id,
    resource_type,
    resource_description,
    request_mode,
    request_status
FROM sys.dm_tran_locks
WHERE resource_type IN ('KEY', 'PAGE', 'OBJECT');

// 输出，Object表示使用的是表锁 
65 OBJECT X GRANT
```

```sql
select * from test where id = '1231' // 被阻塞
```

笔者将表的锁升级改为禁用，也会自动升级为表锁，好神奇

由此可推断出笔者代码符合死锁产生的互斥的条件

## 解决办法

1、首先就是对代码逻辑的修改，之前对于一条相同数据的获取笔者使用了多次走数据库查询，修改为直接由第一次查询完后带来，不用重复查询

```java
 @Override
 public String sendMsg(ChatSendMsgReq req, String uid) {
     AbstractWebsocketMsgHandler handler = WebsocketMsgHandlerFactory.getByType(req.getMsgtype());
     ImMessage msg = handler.checkAndSaveMsg(req, uid);
     // 直接带入，后续操作无需再次查询
     applicationEventPublisher.publishEvent(new MessagePushEvent(msg, this));
     return msg.getId();
 }
```

2、其次对于保存，由于笔者对整个方法使用 `@Transactional` 进行了事务控制，事务的粒度比较大，改为只对数据库操作的部分加上事务

```java
public ImMessage checkAndSaveMsg(ChatSendMsgReq request, String uid) {
    T body = this.toBean(request.getBody());
    //统一校验
    AssertUtil.allCheckValidateThrow(body);
    //子类扩展校验
    checkMsg(body, request.getRoomid(), uid);
    ImMessage insert = ImMessage.buildMsgSave(request, uid, request.getBody());
    return transactionTemplate.execute(status -> {
        //统一保存
        imMessageMapper.insertImMessage(insert);
        //消息其他处理
        handleMsg(insert, body);
        return insert;
    });
}
```

3、然后就是会话更新逻辑，笔者之前做法是通过定时任务，每隔5秒就调用后端接口去更新会话最新读取时间，造成了大量的无效请求，浪费了系统的资源，改为只有自己主动发送消息和接受到消息才进行读取

4、最后就是新增重试机制，对于发送失败的数据进行重试，最多重试3次

```java
while (failList.size() > 0) {
    if (retryCount == 0) {
        break;
    }
    List<ImRoomSingle> tempList = new ArrayList<>();
    try {
        Thread.sleep(1000);
        for (ImRoomSingle imRoomSingle : failList) {
            try {
                chatService.sendMsg(AppMsg.buildAppMsgChatReq(imRoomSingle.getRoomid(), appMsg), appid);
            } catch (Exception e) {
                log.error("【重试】发送消息失败，原因：{}", e.getMessage(), e);
                tempList.add(imRoomSingle);
            }
        }
    } catch (InterruptedException e) {
    }
    failList.clear();
    failList = tempList;
    retryCount --;
}
```
