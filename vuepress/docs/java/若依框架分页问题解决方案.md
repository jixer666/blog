## 问题一复现

若依使用的分页是开源的 `pagehelper` 框架，出错的代码如下：

```java
@PreAuthorize("@ss.hasPermi('blog:article:list')")
@GetMapping("/list")
public TableDataInfo list(BlogArticle blogArticle)
{
    startPage();
    List<BlogArticle> list = articleService.selectArticleList(blogArticle);
    return getDataTable(list);
}

@Override
public List<BlogArticle> selectArticleList(BlogArticle blogArticle)
{
    if (!SecurityUtils.isAnonymous() && !SecurityUtils.isBlogAdmin() && !SecurityUtils.isAdmin()) {
        blogArticle.setUserId(SecurityUtils.getUserId());
    }
    List<BlogArticle> blogArticles = articleMapper.selectArticleList(blogArticle);
    List<Long> userIds = blogArticles.stream().map(BlogArticle::getUserId).collect(Collectors.toList());
    Map<Long, SysUser> userMap = userService.selectUserList(userIds)
            .stream()
            .collect(Collectors.toMap(SysUser::getUserId, Function.identity()));
    return blogArticles.stream().map(item -> {
        SysUser user = userMap.get(item.getUserId());
        fillArticleUiParams(item, user);
        return item;
    }).collect(Collectors.toList());
}

protected TableDataInfo getDataTable(List<?> list)
{
    TableDataInfo rspData = new TableDataInfo();
    rspData.setCode(HttpStatus.SUCCESS);
    rspData.setMsg("查询成功");
    rspData.setRows(list);
    rspData.setTotal(new PageInfo(list).getTotal());
    return rspData;
}
```

笔者在查询出所有文章后使用了 stream 流将文章列表的每个对象的进行了赋值，在前端分页调用分页接口的时候会出现返回的记录总数不对的现象

### 问题分析

通过断点排查问题和看  `pagehelper` 框架源码得知， `pagehelper` 框架会将我们查询的列表结果封装成一个 Page 对象

Page 对象继承了 ArrayList，代码如下：

```java
public class Page<E> extends ArrayList<E> implements Closeable {
    // 代码省略
}
```

getDataTable 方法会将列表对象强转为 Page 对象，从而能够通过 getTotal 方法拿到记录总数

因为笔者是通过 stream 流将文章信息进行了赋值，导致原有的 Page 对象结构发送了变化。在 getDataTable 中获取记录总数的时候，因为此时不是 Page 对象，所以拿到的永远是列表的总数

### 方法一

保持原有的对象不变，只单独对具体的对象单独赋值

通过增强 for 循环来进行对每个对象处理

### 方法二

笔者想保持原有代码不大改的情况下，实现列表更替

在参考了 `BaseController` 等代码后，决定写一个 `BaseService`，用一个方法来专门处理对这些列表需要赋值更替的需求

代码如下：

```java
public class BaseService<T> {

    public <T> List<T> pageList2CustomList(List<T> pageList, Function<List<T>, List<T>> processor) {
        List<T> newList = new ArrayList<>(); // 创建新的数组
        newList.addAll(pageList);
        List<T> result = processor.apply(newList); // 处理列表
        pageList.clear(); // 清空原列表
        pageList.addAll(result); // 填充处理后的数据
        return pageList;
    }

}
```

修改后的代码使用如下：

```java
@Override
public List<BlogArticle> selectArticleList(BlogArticle blogArticle)
{
    if (!SecurityUtils.isAnonymous() && !SecurityUtils.isBlogAdmin() && !SecurityUtils.isAdmin()) {
        blogArticle.setUserId(SecurityUtils.getUserId());
    }
    List<BlogArticle> blogArticles = articleMapper.selectArticleList(blogArticle);
    List<Long> userIds = blogArticles.stream().map(BlogArticle::getUserId).collect(Collectors.toList());
    Map<Long, SysUser> userMap = userService.selectUserList(userIds)
            .stream()
            .collect(Collectors.toMap(SysUser::getUserId, Function.identity()));
    return pageList2CustomList(blogArticles, (List<BlogArticle> list)-> {
        return list.stream().map(item -> {
            SysUser user = userMap.get(item.getUserId());
            fillArticleUiParams(item, user);
            return item;
        }).collect(Collectors.toList());
    });
}
```

通过继承 `BaseService`，调用 pageList2CustomList 方法赋予了这个 Service 对象拥有转化列表里元素的权力，并且不会影响原代码的更改，实现了高耦合低内聚

**方法二代码更新**

> 更新时间：2025.8.28

重构了分页列表转化为自定义列表的代码，在原来的基础上增强，适用于自定义实体的转化，之前的代码只适用于固定实体

```java
public class BaseService {
    public <T, OUT> Page<OUT> pageList2CustomList(List<T> pageList, Function<List<T>, List<OUT>> processor) {
        List<OUT> result = processor.apply(pageList);
        Page<OUT> page = new Page<>();
        page.addAll(result);
        page.setTotal(((Page) pageList).getTotal());
        return page;
    }
}
```

## 问题二复现

时间发现于 2025.8.24

公司项目中在分页的时候，使用 `startPage()` 开启分页后，我在查询分页数据之前做了一个前置校验，然后才做的查询列表，分页就没有起作用，查询的全部的列表数据

### 问题分析

再次查询 PageHelper 源码，在 `PageInterceptor` 中，它会对 SQL 查询语句进行拦截

```java
@Override
public Object intercept(Invocation invocation) throws Throwable {
    try {
		// 省略
        //调用方法判断是否需要进行分页，如果不需要，直接返回结果
        if (!dialect.skip(ms, parameter, rowBounds)) {
            // 省略
        } else {
            //rowBounds用参数值，不使用分页插件处理时，仍然支持默认的内存分页
            resultList = executor.query(ms, parameter, rowBounds, resultHandler, cacheKey, boundSql);
        }
        return dialect.afterPage(resultList, parameter, rowBounds);
    } finally {
        if (dialect != null) {
            dialect.afterAll();
        }
    }
}
```

`dialect.skip` 方法会检查是否存在 Page 分页参数，若不存在就走默认的逻辑，否则就走动态添加分页参数的逻辑

`dialect.afterAll` 方法会对 Page 参数进行清除

由此可见，PageHelper 的分页参数逻辑只会在第一次查询的时候添加，第二次查询的时候就走的默认的查询

### 方法

在前置校验后才加上 `PageUtils.startPage()`，保证只在需要分页查询的时候触发一次
