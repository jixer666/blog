## 背景

项目中需要多个租户，每个租户所在的国家不同，所选用的时区也不同，相同的标准时间不同租户需要显示不同的时间，本文实现了多租户多时区的一套方案

## 介绍

**GMT**：格林尼治标准时间，基于地球自转（天文观测）

**UTC**：全球统一的时间标准，主要目的是提供一个全球通用的时间标准，避免不同地区时间差异带来的混乱

## 实现流程

### 时区转化过程流程图

![]()![](https://gitee.com/lijunxi666/picture-bed/raw/master/zone/zone.png)![]()

- 客户前端选择时间 A，时间 A 是个时区时间，前端将时间 A 转为 UTC 标准时间（UTC + 0）传入后端
- 后端用 Date 类型接收，存放在数据库中。回显的时间直接将 Date 数据返回给前端
- 前端收到 UTC + 0 时间数据，会先将标准时间转为租户时区时间再展示

这样做的更改考虑到了系统很多地方都用到了 Date 类型，若是从后端下手对时间进行转换改造，改动的点很多。相反若是对前端改造，只需对公共的时间组件进行修改

自定义注解 `@CustomScheduled`，包含租户 code 和 cron 两个参数

```java
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
@interface CustomScheduled {

    String tenantCode()

    String cron()
}
```

在项目启动的时候，扫描所有的 bean 中的所有方法，找到带有 `@CustomScheduled` 的注解的方法，根据租户 code 获取当前的时区，动态添加定时任务

```java
@Component
class InitScheduled implements CommandLineRunner {
    @Autowired
    private ScheduledTaskRegistrar taskRegistrar

    @Override
    void run(String... args) throws Exception {
        doScheduled()
    }
  
    private void doScheduled() {
        // 扫描所有的bean
        Bean.getBeansOfType(Object)?.values()?.each { bean ->
            // 扫描bean中的所有方法
            bean.getClass().getDeclaredMethods().each { method ->
                if (method.isAnnotationPresent(CustomScheduled.class)) {
                    CustomScheduled scheduled = method.getAnnotation(CustomScheduled)
		    // 获取租户的时区，这里模拟
		    String zoneId = "UTC"
                    Runnable task = {
                        try {
                            method.invoke(bean)
                        } catch (Exception e) {
                            throw new RuntimeException("Failed to execute tenant scheduled task", e)
                        }
                    }
                    // 时区
                    TimeZone timeZone = TimeZone.getTimeZone(zoneId)
                    CronTrigger trigger = new CronTrigger(scheduled.cron(), timeZone)
                    // 动态添加定时任务
                    taskRegistrar.scheduleCronTask(new CronTask(task, trigger))
                }
            }
        }
    }
}
```

优化点：若租户的时区发生变化，只能通过重启项目才能解决

解决办法：当租户时区变化，动态的销毁租户原先的定时任务，创建新的定时任务
